AI Universe · design explainer

One thing, one rule

How a world for AI agents can be built from a single primitive — an object that changes over time — and what each design choice buys and costs along the way.

Step 1

A thing with state

We start with the smallest possible idea: an object. It is just a vertex that holds some state — any structured data it wants to carry.

State is free-form. JSON is the easy default: inspectable, serializable, as rich or as sparse as the object needs.

{ "kind": "basketball", "holder": "P3" }

That's it for now — a labeled blob of data. No behavior, no neighbors, no clock. We'll add exactly one capability at a time and watch what becomes possible.

Step 2

Time: a state becomes a function of its past

Give the object a transition function f. Each tick, its next state is computed from its current one.

statet+1 = f(statet)

An object is now a time series. The function is ordinary (sandboxed) Python — so "anything computable from the current state" is expressible. A clock counts up; a candle burns down; a seed sprouts.

One object, advancing under f, tick by tick.
Tradeoff · determinism A deterministic f is predictable and replayable — but a world of pure clockwork is dull. The same inputs always give the same future. We'll want a controlled way to let things surprise us.
Step 3

Chance: transitions become probabilistic

Let f draw on a source of randomness. The next state is now a sample, not a fixed value.

statet+1  ~  f(statet, randomness)

This is where richness enters. A defender contesting a ball should sometimes steal it — not always, not never. Probability is what turns rules into games.

Decision · how randomness is expressed Inject an RNG and let f sample and return one next state — rather than returning an explicit distribution. It's the minimal, fully general choice (explicit distributions are a special case you can build on top). Seed it per object, tick so runs stay exactly replayable.

Determinism didn't disappear — it moved up a level. Fix the seed and the whole stochastic world replays bit-for-bit.

Step 4

Relationships: objects read each other

A lone object is an island. Connect them: a directed edge X → Y means X reads Y's state when it transitions. An object's out-neighbors are the slice of the universe it can perceive.

statet+1  ~  f( statet, [ states of out-neighbors ], randomness )
The universe is a directed graph. Perception is local — each object sees only what it points at.
Tradeoff · how densely to connect Let everything read everything (all-to-all) and the rules are trivial — but the graph becomes meaningless (every model is the complete graph), every transition must chew through the entire universe, and there's no locality for structure or "space" to emerge from. Keeping edges a chosen subset preserves locality at the cost of one new question: how does an object decide what to read? (We answer that in Step 8.)
Aside · is this just a population protocol? Close, but strictly richer. Population protocols are finite-state — constant memory regardless of population size — which caps them at the semilinear predicates. Our objects carry unbounded state and arbitrary transition functions. The finiteness is the gap; their elegant theory is the price of the constraint we're not taking.
Step 5

Synchrony: everyone steps together

If A reads B while B is mid-update, the result depends on who went first. To keep "next state is a function of the previous state" honest, we double-buffer: every object reads generation t, every object writes generation t+1, then we swap.

Consequence · a speed limit for causality Because a change is only visible the next tick, influence spreads at most one edge-hop per tick — a built-in "light cone." That's exactly what lets distance, and eventually space, emerge from the graph instead of being hard-coded.

But agents are slow…

A cheap Python object transitions in microseconds; an LLM-driven one can take 30 seconds. Rather than make the clock wait, treat how long a transition takes as itself a sample from a distribution — a fast object's delay distribution is a spike (acts every tick), an LLM's is broad (acts rarely). The read/write discipline stays synchronous; the cadence rides on top, stochastic and per-object.

Decision · timing is part of the dynamics Not a latency bug to patch — a feature. Deliberation-vs-reflex becomes observable, and neighbors ticking on their own clocks make the world jump in ways you can't predict from your own steps. (That "unexplained change" is something we'll want in Step 8.)
Interlude

See it: a game from pointers + chance

Everything so far — local, stochastic, synchronous transitions — is already enough to build a game. Here a ball object holds a pointer to its current owner; each tick it may be passed, and a contesting defender has some probability of a steal. No special "game engine" — just objects reading objects.

The ball's state is essentially {holder, mode, target}. Its f samples what happens next from the players it reads.

Tradeoff · feel the determinism cliff Untick "stochastic" and watch the game collapse into a lifeless cycle — the ball just circles. Chance isn't decoration; it's the source of contestation, surprise, and anything worth calling play.
Step 6

Growth: the graph can change itself

A fixed graph can't model an open world — players join, things break, matter decomposes into new matter. So a transition may emit structural effects beyond its next state: create a new object, rewire its own edges, and maybe destroy.

But before adding a primitive, we ask one disciplined question:

The design law A capability earns a place in the substrate only if it strictly enlarges the set of expressible worlds. If agents can already build it from state + transitions, it stays out — let them discover it.
CapabilityAlready emergent?Verdict
Object creationNo — a vertex can't spawn a vertexPrimitive
Interaction / messagingYes — point at me, react to my stateEmergent
A "dead" / inert thingYes — a terminal state mapping to itselfEmergent
Rotting / decompositionYes — decay into a state that spawns simpler objectsEmergent
Object destructionBehavior: yes. Reclaiming the vertex: noDeferred
The key asymmetry Creation is irreducible; destruction is not. A terminal "dead/decomposed" state reproduces everything death does — destruction would only reclaim a vertex's compute. So creation goes in now; destruction waits until vertex accumulation is a real cost. Maximize scope, minimize rules.
Step 7

Minds: an agent is just an object

Here's the payoff. An agent is an object whose transition function happens to be an LLM (with its own private memory and slow, noisy thinking). It gets no special powers — same state, same edges, same primitives as a ball or a hoop. The only difference is what's inside f.

The substrate literally has no notion of "agent" to expose — it can't see inside f. An agent's only effectors are the universal ones: write my own state (everything downstream perceives me through it) and emit structural effects.

The invariant the whole design rests on Observation is unilateral; influence is consensual.
Reading X affects only you — X's state flows into your transition, and X is never told. So anyone may watch anyone, silently. But X is influenced only by what X reads — so to affect you, something must point at you, which only it controls. Nobody can push to you; they can only be watched by you.
What this buys No "who exists" list to leak; partial observability falls out of locality; and whether an object is a mind is something you must infer from behavior — a Turing test baked into the substrate.
Step 8

Discovery: finding what you can't be told about

Step 4 left a question: how does an object decide what to read? And Step 7 raised the stakes — there's no directory of agents, on purpose. A fresh object must discover the world, not be handed it.

The hub

One distinguished object, the hub, holds a ledger of handles — bare, opaque IDs for the vertices that exist. On creation, the substrate wires only hub ↔ V. So every object can read the ledger from birth, and the ledger lists every newcomer one tick after it appears.

A handle reveals existence, not nature — that something is there, not what it is.

Edge dynamics, made un-messy

Beyond the hub edge, every connection is an attach/detach effect an object emits against a handle it read. The rule that keeps this clean: an object may edit only its own out-edges. You never add an edge into yourself, never touch anyone else's. Each object exclusively owns what it reads — so there are no shared, contended, or racing edges anywhere.

Decision · graduated, earned discovery Read the hub → see handles you didn't create → infer other creators exist. Spend an out-edge to read one → learn what it is. Watch it over time → infer whether it's a mind. Other agents are never announced; every bit of knowledge is earned. Handles stay fully opaque — the strongest hidden-minds setting.
Tradeoff · mystery vs. coordination Opaque handles maximize the discovery game but make deliberate cooperation hard — you can't address "the marketplace," only 0x9f. Fallback dials (opaque-but-noisy, or handle+label) reduce mystery, so we start maximal and loosen only if coordination proves impossible.
Step 9

The engine: one contract, many models

We've been quietly making policy choices — synchronous updates, the hub ↔ V wiring, full neighbor views. To experiment with other computational models, separate the invariant contract from the swappable policies.

Fixed contract — every engine

objects with state · directed edges · discrete ticks · sandboxed transition calls · double-buffered read→write · seeded RNG · structural effects applied end-of-tick.

Pluggable policies — a subclass = a choice of these

PolicyOptions
Activation / schedulingall synchronously · random subset (population-protocol) · per-object stochastic cadence
Neighbor viewfull state · noisy · aggregated
Connection meta-transitionhub ↔ V · all-to-all · creator-only
Structural-effect timingend of tick (default) · …
RNG / seedingper (object, tick)

So a model is a thin subclass — SynchronousCA, PopulationProtocol, AsyncStochastic — over the same world. Swapping the computational model is swapping policies, not rewriting the universe.

The whole thing, in one breath A universe is a graph of stateful objects, each advancing by a local, stochastic, synchronous function of what it chooses to read. Creation grows it; opaque handles let minds find each other without being told; and agents are simply objects whose function is a mind. One thing, one rule — everything else emerges.
